# 反馈功能API文档

## 概述
本文档描述了假条自动生成页面中反馈功能所需的后端API接口规范。

## API端点

### 提交反馈

- **URL**: `/api/feedback/`
- **方法**: `POST`
- **认证**: 不需要（无需登录即可提交反馈）
- **内容类型**: `application/json`

**请求体参数**:

```json
{
  "name": "用户姓名",          // 可选，字符串
  "email": "user@example.com", // 可选，字符串，有效的电子邮件地址
  "type": "suggestion",        // 必填，字符串，取值: "suggestion", "bug", "question", "other"
  "content": "反馈内容",       // 必填，字符串
  "source": "autops"           // 可选，字符串，表示反馈来源页面
}
```

**成功响应** (HTTP 状态码 201):

```json
{
  "id": 123,                   // 反馈ID
  "status": "received",        // 反馈状态
  "created_at": "2025-09-14T10:30:00Z",  // 创建时间
  "message": "感谢您的反馈"    // 可选的消息
}
```

**错误响应** (HTTP 状态码 400):

```json
{
  "error": "validation_error",
  "message": "反馈内容不能为空",
  "fields": {
    "content": ["此字段为必填项"]
  }
}
```

## 字段说明

| 字段名     | 类型     | 必填  | 描述                                           |
|-----------|----------|------|------------------------------------------------|
| name      | 字符串   | 否    | 提交反馈的用户姓名                              |
| email     | 字符串   | 否    | 用户电子邮箱，用于回复反馈                      |
| type      | 字符串   | 是    | 反馈类型，可选值：suggestion, bug, question, other |
| content   | 字符串   | 是    | 反馈的具体内容                                 |
| source    | 字符串   | 否    | 反馈来源页面，例如："autops"表示来自假条生成页面 |

## 注意事项

1. 后端应对反馈内容进行安全过滤，防止XSS攻击
2. 电子邮箱字段应进行有效性验证
3. 建议实现速率限制，防止恶意提交大量反馈
4. 对于包含敏感内容的反馈，建议实现内容审核机制
